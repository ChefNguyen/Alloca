# ALC-41 and My Bookings — executed verification, 2026-11-08

ALC-41 and the My Bookings frontend integration are implemented in the local
workspace. This records executed checks; it does not change remote Jira status.

## Delivered behavior

- `GET /api/v1/bookings`: database-side owner scope, filtering, stable sorting,
  pagination and scoped totals. Employee sees self; Manager sees self and owners
  in their current department; Admin sees all. A departmentless Manager sees self.
- `GET /api/v1/bookings/{id}`: flat booking detail with chronological status history.
- `GET /api/v1/bookings/{id}/history`: separate timeline with the same authorization.
  A creator has no extra access after losing owner-department scope. Historical
  records remain readable after resource soft deletion when owner scope allows it.
- Date filters use overlap with `[from,to)`. Owner, department, resource and status
  filters only narrow authorized rows; scope is applied before counting/pagination.
- Delegated creation acceptance checks include same-department Manager, cross-scope
  Employee/Manager rejection, Admin delegation, inactive target rejection and forged
  creator rejection. The authenticated principal remains the creator.
- My Bookings loads server data, defaults to self, and supports wider authorized
  scope, status/date filters, sorting, pagination, details/history and reasoned
  cancellation. Loading/error/empty/retry states are explicit. Mutations refetch
  server state; errors never synthesize a successful local booking/cancellation.
- The shared booking form uses real availability and resource/active-owner pages.
  It permits only contiguous free half-hour slots up to eight hours, handles 409 by
  refreshing availability, and discards stale asynchronous responses. Resource and
  delegate selection are disabled while replacement search results are loading.
- Business dates/times are displayed in Asia/Ho_Chi_Minh. Commands preserve UTC
  instants from availability. The global modal no longer depends on mock bookings
  or resources; existing resource-list/detail entry points use the same live form.

jar. It exclusively creates its own database, binds to loopback ports 15436/18083,
uses synthetic fixture accounts, and refuses to replace existing services on those
ports. Frontend interaction tests run in jsdom, not an automated browser; visual
inspection remains a manual check at `/my-bookings`.
